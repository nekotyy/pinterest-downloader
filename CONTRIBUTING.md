# Участие в разработке

Репозиторий приватный. Для работы с ним нужен доступ, предоставленный владельцем. Ошибки и предложения можно описать через вкладку Issues; вопросы по использованию удобно обсуждать в Discussions. Не публикуйте пароли, cookies, закрытые ссылки и другие личные данные в сообщениях и журналах.

## Подготовка

Для разработки нужны Git, .NET 8 SDK и Node.js. Для проверки расширения нужен браузер на Chromium или Firefox.

```powershell
git clone https://github.com/nekotyy/pinterest-downloader.git
cd pinterest-downloader
dotnet run
```

Для Chromium загрузите папку `extension` как распакованное расширение. Для Firefox откройте `about:debugging#/runtime/this-firefox` и выберите `extension-firefox/manifest.json`. Временное расширение Firefox удаляется после перезапуска браузера.

## Проверки

Запустите проверки перед отправкой изменений:

```powershell
node tests/extension.test.js
dotnet run --project tests/HistoryChecks/HistoryChecks.csproj
```

Первая команда проверяет синхронизацию, настройки и команды расширения на моделируемых вкладках. Вторая проверяет историю, фильтрацию, загрузку и очередь команд. GitHub Actions дополнительно собирает приложение и проверяет его запуск и локальное соединение на Windows и Linux.

Если изменение затрагивает интерфейс или работу с Pinterest, дополнительно проверьте его вручную в нужных системе и браузере. Не закрывайте чужие вкладки и не используйте реальные личные данные в тестовых фикстурах.

## Структура

- `MainWindow.cs`: интерфейс и локальный HTTP-обмен с расширением.
- `BrowserRegistry.cs`, `CloseCommands.cs`: состояние браузеров и очередь закрытия вкладок.
- `DownloadHistory.cs`, `ImageDownloader.cs`, `PinFilter.cs`: история, загрузка и фильтрация.
- `AppPreferences.cs`, `SettingsDialog.cs`: настройки и их окно.
- `extension`, `extension-firefox`: версии расширения для Chromium и Firefox.
- `tests`: проверки расширения, логики приложения и запуска сборок.

Общие файлы расширения должны совпадать в обеих папках. Это проверяет `tests/extension.test.js`.

## Изменения

1. Создайте ветку для изменения и опишите решаемую задачу в Issue или Pull Request.
2. Сохраните совместимость с данными пользователя, проверьте обработку ошибок и добавьте тест для новой нетривиальной логики.
3. В Pull Request укажите, что изменилось и какие проверки запускались.
4. Не добавляйте в репозиторий собранные файлы, cookies, токены и личные данные.
